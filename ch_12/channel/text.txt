Goroutines communicate using channels. Like slices and maps, 
channels are a built-in type created using the make function:
ch := make(chan int) Like maps, channels are reference types.

a := <-ch // reads a value from ch and assigns it to a 
ch <- b // write the value in b to ch

=== UNBUFFERED CHANNEL ===
By default, channels are unbuffered. Every write to an open, 
unbuffered channel causes the writing goroutine to pause until 
another goroutine reads from the same channel. Likewise, a read from an open, 
unbuffered channel causes the reading goroutine to pause until another 
goroutine writes to the same channel. This means you cannot write to or 
read from an unbuffered channel without at least two concurrently running goroutines.

=== BUFFERED CHANNEL ===
Go also has buffered channels. These channels buffer a limited number of writes 
without blocking. If the buffer fills before there are any reads from the channel,
a subsequent write to the channel pauses the writing goroutine until the channel
is read. Just as writing to a channel with a full buffer blocks, reading from a 
channel with an empty buffer also blocks.



####  Unbuffered Channels (Buferlanmagan kanallar):
ch := make(chan int)
    Sig‘imi 0 ga teng.
    Ma’lumot jo‘natuvchi (`ch <- val`) boshqa bir goroutina ma’lumotni qabul
     qilib olmaguncha (`<-ch`) bloklanib (kutib) turadi. Ikkala goroutina 
     uchrashgandagina ma’lumot o‘tadi.

###  Buffered Channels (Buferlangan kanallar):
    ch := make(chan int, 10)
    Belgilangan hajmga (sig‘imga) ega bo‘ladi
    Jo‘natuvchi bufer to‘lmaguncha bloklanmay ma’lumot yuboraveradi.
    Qabul qiluvchi esa bufer bo‘sh bo‘lsa kutib turadi.



Kanallarni yopish: close(ch) orqali amalga oshiriladi.
Yopilgan kanalga ma’lumot yozish panic beradi.

Yopiq kanaldan o‘qish: Yopilgan kanaldan ma’lumot o‘qish mumkin! 
Agar buferda ma’lumot bo‘lsa ular o‘qiladi, bufer tugagach esa kanal 
turining nol qiymati (`zero value`) qaytadi.

v, ok := <-ch if !ok { // kanal yopilgan va bo'sh }
